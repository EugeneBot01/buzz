# 97-files-and-deletes.patch — 파일 찾기 · 한 번에 받기 · 지운 메시지 · 받기 오류 안내

- 기준: `desktop-v0.5.28` + `10`~`96` 위.

## 1. 파일 모아보기에서 이름으로 찾기 (`60` 확장)
- 채널 파일 창 맨 위에 "파일 이름으로 찾기" 칸. 띄어쓰기로 나눈 낱말이 **모두** 이름에 들어 있는 파일만 보인다(대소문자 무시, `searchFiles`).
- "전체 선택"과 개수 표시는 찾은 파일 기준. 찾는 파일이 없으면 "이전 메시지에서 더 찾기"로 더 불러오라고 안내한다(창은 최근 메시지부터 불러온다).

## 1-1. 파일 목록이 수정·삭제를 따르게 (`60` 버그 수정)
- 원인: 파일 창이 메시지를 **처음 올린 모습**으로만 읽었다. 메시지를 고쳐 파일을 바꾸거나 늘려도 예전 파일만 보였고, 지운 메시지의 파일도 남았다(실제 사례: 공모전 공유 채널, 파일 2개짜리 메시지가 수정 전 이름의 1개로 보임).
- 고침: 수정(kind 40003)·삭제(kind 5, 9005)도 함께 불러와, 메시지마다 작성자 본인의 최신 수정이 가진 첨부 목록을 쓰고(타임라인과 같은 `applyEditTagOverlay`), 지운 메시지는 뺀다. "이전 메시지에서 더 찾기"는 메시지 시각으로만 페이지를 넘긴다.

## 2. 메시지 하나에 붙은 파일 한 번에 받기
- 파일이 2개 이상 붙은 메시지 아래에 "파일 N개 모두 받기" 버튼(`MessageFilesDownloadButton`). 폴더를 한 번 고르면 그 메시지의 파일이 모두 저장된다(`download_files_to_folder`, `60`과 같은 명령).
- 파일 창과 버튼은 같은 받기 함수를 쓴다(`lib/bulkDownload.ts`).
- 연결: `features/messages/ui/MessageRow.tsx` 본문 아래 한 줄.

## 3. 지운 메시지가 스레드 창에 남던 문제
- 원인: 지우기가 채널 타임라인 캐시(`channelMessagesKey`)에서만 빼고, 스레드 창이 따로 쓰는 `["thread-replies", 채널, 루트]` 캐시는 그대로 둬서, 앱이 다시 불러올 때까지 지운 답글이 스레드에 보였다. 인박스에서 지울 때는 채널·스레드 캐시를 아예 건드리지 않았다.
- 고침: `forgetDeletedMessage`가 채널 캐시와 그 채널의 모든 스레드 캐시에서 빼고, 스레드 캐시는 다시 불러온다. 채널 화면(`useDeleteMessageMutation`)과 인박스(`HomeView`) 양쪽에서 쓴다.

## 4. 파일 받기 실패 안내
- 받기 실패 토스트가 영어 원문("download URL must match the relay origin" 등)이었다. `downloadErrorText`가 원인별 한국어 안내로 바꾼다.
  - 다른 커뮤니티 서버의 파일(주소의 서버가 지금 연결된 커뮤니티와 다름): 앱 재시작 후 그 커뮤니티에서 받기. 커뮤니티 전환이 꼬였을 때(block/buzz#7518)도 이 경우다.
  - 너무 큼(512MB 초과), 서버 거절(401/403: 맥 시계 확인), 없음(404), 시간 초과.
- 앱은 보안상 **지금 연결된 커뮤니티 서버의 `/media/` 주소만** 받는다. 이 규칙은 그대로 둔다.
