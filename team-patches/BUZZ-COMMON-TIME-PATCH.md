# 106-common-time.patch — 함께 되는 시간 찾기

103 팀원 일정에서 가능한 시간을 비교하고, 추천 시간으로 캘린더 일정 입력창을 연다.

- 기준: `desktop-v0.5.28` + `10`~`105` 패치.

## 1. 범위

- 일정 → 팀 캘린더 → **팀원 일정** → **함께 되는 시간 찾기**.
- 날짜는 오늘부터 14일, 필요한 시간은 1시간, 찾을 시간대는 09:00~22:00, 대상은 전원이 기본이다. 꼭 와야 하는 인원을 따로 고른다.
- 추천 최대 8개, 30분마다 시작하는 표, 가능·불가·조율 명단과 겹친 일정 제목을 보여 준다.
- 추천의 **이 시간으로 일정 만들기**는 기존 일정 폼에 날짜·시작·종료를 채운다. 저장은 사람이 누른다.

## 2. 동작

- 순수 함수 `lib/commonTime.ts`에서 계산한다. 반복·기간·빠지는 날은 103의 `ruleAppliesOn`을 그대로 재사용한다.
- 전체 길이 중 일부라도 불가면 불가다. 구간은 시작 포함·종료 제외여서 18:00 종료 일정은 18:00 시작 모임을 막지 않는다.
- 불가 > 조율 > 가능. 등록하지 않은 시간은 가능이다. 컴퓨터의 시간대와 무관하게 한국시간의 오늘을 쓴다.
- 정렬: 필수 인원 전원 가능 → 가능 인원 많은 순 → 조율 적은 순 → 날짜·시각 이른 순. 필수 인원이 불가·조율인 후보는 표시로 구분한다.
- 표도 선택한 길이 전체를 계산한다. 색과 함께 가능 인원 수, 필수 인원 상태, 버튼 이름을 표시한다.
- 팀원 일정 읽기가 끝나야 검색을 연다. 읽기 실패 시 다시 읽기 버튼을 제공한다. 날짜·시간·대상 오류를 표시하고, 한 번의 검색은 최대 31일로 제한한다.
- 24:00에 끝나는 추천은 기존 캘린더 형식에 맞춰 다음 날 00:00으로 채운다.

## 3. 의도

외부 빈칸 사이트의 관리자 주소나 개인 링크 없이 Buzz의 기존 팀원 일정 데이터로 계산한다. 검색·명단 열기·일정 입력창 열기는 읽기 전용이며 새 이벤트를 만들지 않는다. 103 패치 파일은 변경하지 않는다.

## 4. 파일·검증

- `lib/commonTime.ts`, `commonTime.test.mjs`: 전체 길이·경계·상태 우선순위·반복/제외/기간·정렬·필수 인원·검색 상한·한국시간.
- `ui/CommonTimePanel.tsx`, `TeamCalendarDialog.tsx`: 입력·추천·표·명단·기존 입력창 연결.
- `ui/commonTime.jsdom-test.mjs`: 실제 캘린더 훅에서 가짜 팀원 문서를 읽어 본문/다이얼로그·자정 종료·자동 저장 없음 검증.
- `tests/e2e/team12.spec.ts`: 가짜 팀원 추가 후 추천→기존 일정 폼까지 브라우저 흐름 검증.

## 5. 빈칸 파일 변환·한계

별도 오프라인 도구 `binkan-to-buzz.mjs`는 `/api/data` 응답 JSON 파일을 `buzz-team-calendar`의 팀원 일정만 있는 파일로 바꾼다. 네트워크를 쓰지 않으며 주소·키·원문 메모를 복사하지 않는다. 제외 항목은 입력 순서와 사유를 별도 보고서에 적는다. 변환 뒤 미리보기를 확인하고 Buzz 가져오기에서 직접 저장한다. 도구와 가짜 입력 테스트는 패치 저장소 밖 `tools/`에 있다.

팀원 일정은 103의 기존 공유 모델을 따른다. 이 패치는 접근 권한이나 저장 방식을 바꾸지 않는다. 실제 개인 일정의 이전·게시와 사람의 실기 확인은 별도다.
