# 104-schedule-tabs.patch — 일정 탭 · 화면 안 링크

103 스프린트 캘린더 위에 팀 공유 링크 탭을 더한다. 기존 103·103b 일정 탭 작업의 새 번호는 104다.

- 기준: `desktop-v0.5.28` + `10`~`103` 패치. `103-sprint-calendar.patch`는 원본 그대로 적용한다.

## 1. 범위

- 사이드바 **일정**에서 팀 캘린더와 링크 탭을 연다. 첫 탭은 항상 팀 캘린더다.
- 방장·관리자는 이름·https 주소·순서·삭제를 편집한다. 팀원은 보기만 한다.
- 링크는 Tauri 자식 웹뷰로 일정 영역 안에 연다. 로그인·쿠키는 기본 저장소를 쓴다. 생성 실패 시 새 창 열기를 제공한다.
- 이 기기 전용 주소는 계정·릴레이·탭별 localStorage에만 저장한다. 공유 이벤트에는 넣지 않는다.
- 105를 함께 적용하면 일정은 본문 전체 화면과 상단 알약 탭으로 열린다.

## 2. 동작

- kind 30078, `d = team-schedule-tabs:<정규화 릴레이>` 문서. 탭 단위 마지막 수정이 이기며 삭제는 `deleted: true`다.
- NIP-43 멤버 목록의 방장·관리자 사본만 인정한다. 기존 링크 주소 검사를 재사용한다.
- 위치는 DOM 영역·화면 배율로 계산한다. 링크 전환, 캘린더, 메뉴·폼·다른 모달에서는 웹뷰를 숨긴다. 일정 이탈과 팀·계정 전환에는 닫는다.
- 외부 페이지에는 Tauri 권한을 주지 않는다. 주 창에는 생성·배치·표시·숨김·닫기 권한만 더한다.
- 103 화면 내용은 공유하고, embedded 본문에는 다이얼로그의 96vw 크기를 적용하지 않는다. 기존 캘린더 다이얼로그 경로를 유지한다.

## 3. 의도

스프린트·달력·팀원 일정·가져오기·배포는 103의 동작을 유지한다. 링크마다 별도 서비스를 다시 구현하지 않고 Buzz 일정 화면에서 기존 페이지를 조작한다. 공유 주소와 기기 전용 주소의 저장 경계는 유지한다.

## 4. 파일·검증

- `features/team-schedule/lib/`: 문서 모델·권한 조회·로컬 주소·웹뷰 수명·위치 계산.
- `features/team-schedule/ui/`: 링크 영역·탭 편집.
- `features/team-calendar/ui/TeamCalendarDialog.tsx`: 내용 공유·embedded 표시.
- `src-tauri/Cargo.toml`, `capabilities/team-schedule.json`: Tauri 자식 웹뷰 설정.
- 순수 함수·DOM 테스트: 공유 사본 권한, 주소 비공유, 위치·전환·숨김·종료·폴백.

## 5. 한계

네이티브 자식 웹뷰의 실제 로그인 유지와 Windows 동작은 각 기기에서 확인해야 한다. 이 기능은 외부 서비스의 로그인·접근 권한을 바꾸지 않는다.
