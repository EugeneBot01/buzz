# 107-availability-production-lock.patch — 팀원 일정 제작부 비밀번호

팀원 일정의 사유는 본인과 제작부만 읽고, 연결된 팀원의 일정은 본인과 제작부만 고친다.

- 기준: `desktop-v0.5.28` + `10`~`106` 패치. 103 원본 패치 파일은 변경하지 않는다.
- 코드 커밋: `73f5a178e` — `107 availability production lock` + `72cb9d505` — `107 polish: easier setup` + `a3975ebad` — `107 polish: add myself` (모두 Signed-off-by 포함). 107 패치는 세 커밋을 합친 `1747dd021..a3975ebad` diff 하나다.

## 1. 범위

일정 → 팀 캘린더 → **팀원 일정** 오른쪽 위에 제작부 상태 버튼 하나가 나온다. 비밀번호가 없으면 방장·관리자에게만 **🔒 제작부 비밀번호 만들기**를 보여 준다. 비밀번호와 **한 번 더**를 적고 저장하면 이 기기가 바로 제작부로 열린다. 길이 제한·안전성 경고는 없다.

설정 뒤에는 **🔒 제작부**에서 비밀번호를 입력하고 **열기**를 누른다. 틀리면 **비밀번호가 맞지 않아요**를 표시한다. **🔓 제작부 보는 중**을 누르면 **잠그기**, 방장·관리자에게는 **비밀번호 바꾸기**도 나온다. **잠그기**는 계정·팀별 기기 기억을 지우고 사유를 즉시 숨긴다. 비밀번호 만들기/바꾸기에는 제작부 톡방 공유 안내가 나온다.

이미 정한 비밀번호를 바꾸려면 제작부를 먼저 연다. 새 비밀번호로 이전에 보호한 사유와 제작부 수정 기록을 이어받으며, 다른 기기의 예전 기억은 새 설정을 받으면 사용할 수 없게 된다.

## 2. 동작

- 새로 저장하는 사유는 작성자 본인(연결된 사람은 그 계정)과 제작부에게 각각 NIP-44로 보관한다. 다른 팀원에게는 불가/가능/조율 종류 이름과 작은 자물쇠가 보인다. 자물쇠에 마우스를 올리거나 키보드로 이동하면 **본인과 제작부만 볼 수 있어요**를 안내한다.
- 날짜·반복·요일·시간·빠지는 날·종류는 그대로라 달력과 106 함께 되는 시간 찾기가 계속 동작한다.
- 비밀번호 설정 전에는 기존 평문 저장이다. 예전 평문은 그대로 읽으며, 제작부 모드가 열려 있으면 자동으로 한 번에 숨겨 다시 저장한다. 만들기/바꾸기 직후와 기기 기억 복원 때도 동작한다. 성공하면 **예전 사유 N개를 숨겼어요**를 한 번 알리고, 실패하면 평문 기록을 유지한 채 다음 조회(30초 주기·재연결·화면 재진입)에 조용히 재시도한다. 진행 중 중복 실행과 잠근 뒤 늦은 게시/알림을 막는다. 별도 숨기기 버튼은 없다. 새 게시에 오래된 평문 사본을 다시 섞지 않는다.
- 연결된 사람의 규칙·이름·역할·삭제는 본인 또는 제작부가 쓴 것만 합친다. `updatedBy` 문자열만 바꾸거나 연결을 지운 제3자 사본은 권한이 되지 않는다. 초기 조회와 실시간 갱신에 같은 검사를 적용한다.
- 아직 내 이름이 연결되지 않았으면 목록 위 이름 카드에서 검색하고 이름을 누른다. **OOO님이 맞나요?** 확인 후 한 번 저장해 연결하고 그 일정을 연다. 연결돼 있으면 화면 진입 시 내 일정을 바로 고른다. 내 행은 맨 위에 **나**, 연결된 사람은 작게 **연결됨**을 표시한다.
- 이름 카드 아래 **목록에 내 이름이 없어요 · 나를 추가하기**는 검색 결과가 없어도 항상 보인다. 이름은 Buzz 표시 이름으로 미리 채우고 역할은 선택이다. **추가**는 새 사람 생성과 내 계정 연결을 한 번에 저장한 뒤 내 일정을 연다. 같은 이름의 미연결 사람이 있으면 **OOO님이 목록에 있어요. 이 이름으로 연결할까요?**를 확인해 기존 사람에 연결하며 역할·일정은 보존한다. **찾는 이름이 없어요.** 안내도 버튼과 함께 유지한다. 실패하면 입력과 오류를 남겨 다시 시도할 수 있다.
- 연결 안 된 사람은 누구나 수정할 수 있다. **이 사람이 나예요**는 연결 안 된 사람에게만 제공한다. 기존 연결 해제·다른 이름으로 변경은 제작부만 한다. 한 번에 연결을 옮기는 동작도 한 게시로 처리한다.
- 화면의 정보 수정·삭제·일정 추가·수정·삭제 버튼도 같은 권한으로 숨긴다. 저장 직전에 최신 목록으로 다시 확인한다.
- 백업 파일은 보호된 사유를 그대로 보관하며 가져오기 때 종류 이름으로 덮지 않는다. 제작부가 연결 계정을 바꾸면 새 본인이 사유를 읽을 수 있도록 다시 보관한다.

## 3. 저장

기존 kind 30078의 `team-availability:<정규화한 릴레이>`와 설정용 `:production` 좌표를 사용한다. scrypt(N=16384, r=8, p=1, 32바이트)와 커뮤니티 주소로 제작부 계정을 결정한다. 처음 공유하는 설정은 공개값뿐이며, 비밀번호·비밀값은 공유하지 않는다. 기기 기억은 계정·팀별 localStorage다. 본인 계정의 비밀값은 네이티브 안에 둔다.

릴레이는 로그인한 계정과 다른 작성자의 직접 게시를 거부한다. 따라서 제작부 수정은 제작부가 서명한 내부 문서를 실제 팀원 계정의 이벤트에 담는다. 읽을 때 내부 서명·종류·정확한 문서 좌표를 검사한다. 비밀번호 교체는 새 제작부 서명으로 기존 보호 기록을 담은 관리자 문서 하나를 게시한다. 크기 초과나 게시 실패는 부분 성공으로 처리하지 않는다.

## 5. 적용·확인

팀원 모두 107 적용본을 사용한다. 구버전은 이 읽기 검사를 하지 않는다. 이미 다른 기기에 배포된 평문·과거 이벤트·파일을 삭제하는 기능은 아니다. 개인 사유에만 적용하는 팀판 결정이며 일반 대화·일정의 검색/접근 모델은 그대로다.

가짜 팀원·가짜 사유로 다음 순서를 확인한다: 이름 카드 검색 → 확인해 연결(또는 **나를 추가하기** → 이름/역할 → **추가**, 같은 미연결 이름은 확인 후 **연결**) → 내 일정 자동 선택 → 관리자 비밀번호 두 번 입력 → 자동 사유 숨기기 알림 → 일반 팀원의 사유/수정 버튼 숨김과 자물쇠 → 잘못된 비밀번호 → 올바른 비밀번호로 제작부 열기 → 잠그면 다시 숨김 → 관리자 비밀번호 바꾸기. 실제 팀 자료의 게시·배포·사람의 직접 확인은 별도다.

이번 보강 검증: 전체 일반 테스트 **7,007** + DOM 테스트 **196** = **7,203 통과**, 실패/건너뜀 **0**. TypeScript·데스크톱 빌드·변경 파일 Biome·px 텍스트 검사 통과. 네이티브 파일은 보강에서 변경하지 않았다.
