# 107-availability-production-lock.patch — 팀원 일정 제작부 비밀번호

팀원 일정의 사유는 본인과 제작부만 읽고, 연결된 팀원의 일정은 본인과 제작부만 고친다.

- 기준: `desktop-v0.5.28` + `10`~`106` 패치. 103 원본 패치 파일은 변경하지 않는다.
- 코드 커밋: `73f5a178e` — `107 availability production lock` (Signed-off-by 포함).

## 1. 범위

일정 → 팀 캘린더 → **팀원 일정** 위쪽에서 방장·관리자가 **제작부 비밀번호 정하기**를 누른다. 비밀번호 길이 제한·안전성 경고는 없다. 모든 팀원은 **제작부 열기**로 비밀번호를 입력하고 이 기기에서 제작부가 될 수 있다. 틀리면 **비밀번호가 맞지 않아요**를 표시한다. **제작부 잠그기**는 계정·팀별 기기 기억을 지우고 사유를 즉시 숨긴다.

이미 정한 비밀번호를 바꾸려면 제작부를 먼저 연다. 새 비밀번호로 이전에 보호한 사유와 제작부 수정 기록을 이어받으며, 다른 기기의 예전 기억은 새 설정을 받으면 사용할 수 없게 된다.

## 2. 동작

- 새로 저장하는 사유는 작성자 본인(연결된 사람은 그 계정)과 제작부에게 각각 NIP-44로 보관한다. 다른 팀원에게는 불가/가능/조율 종류 이름만 보인다.
- 날짜·반복·요일·시간·빠지는 날·종류는 그대로라 달력과 106 함께 되는 시간 찾기가 계속 동작한다.
- 비밀번호 설정 전에는 기존 평문 저장이다. 예전 평문은 그대로 읽으며, 제작부의 **예전 사유 숨기기**가 현재 사유를 한 번에 다시 저장한다. 새 게시에 오래된 평문 사본을 다시 섞지 않는다.
- 연결된 사람의 규칙·이름·역할·삭제는 본인 또는 제작부가 쓴 것만 합친다. `updatedBy` 문자열만 바꾸거나 연결을 지운 제3자 사본은 권한이 되지 않는다. 초기 조회와 실시간 갱신에 같은 검사를 적용한다.
- 연결 안 된 사람은 누구나 수정할 수 있다. **이 사람이 나예요**는 연결 안 된 사람에게만 제공한다. 기존 연결 해제·다른 이름으로 변경은 제작부만 한다. 한 번에 연결을 옮기는 동작도 한 게시로 처리한다.
- 화면의 정보 수정·삭제·일정 추가·수정·삭제 버튼도 같은 권한으로 숨긴다. 저장 직전에 최신 목록으로 다시 확인한다.
- 백업 파일은 보호된 사유를 그대로 보관하며 가져오기 때 종류 이름으로 덮지 않는다. 제작부가 연결 계정을 바꾸면 새 본인이 사유를 읽을 수 있도록 다시 보관한다.

## 3. 저장

기존 kind 30078의 `team-availability:<정규화한 릴레이>`와 설정용 `:production` 좌표를 사용한다. scrypt(N=16384, r=8, p=1, 32바이트)와 커뮤니티 주소로 제작부 계정을 결정한다. 처음 공유하는 설정은 공개값뿐이며, 비밀번호·비밀값은 공유하지 않는다. 기기 기억은 계정·팀별 localStorage다. 본인 계정의 비밀값은 네이티브 안에 둔다.

릴레이는 로그인한 계정과 다른 작성자의 직접 게시를 거부한다. 따라서 제작부 수정은 제작부가 서명한 내부 문서를 실제 팀원 계정의 이벤트에 담는다. 읽을 때 내부 서명·종류·정확한 문서 좌표를 검사한다. 비밀번호 교체는 새 제작부 서명으로 기존 보호 기록을 담은 관리자 문서 하나를 게시한다. 크기 초과나 게시 실패는 부분 성공으로 처리하지 않는다.

## 4. 파일·검증

- `availabilityPrivacy.ts`: 결정적 제작부 계정, 두 수신자의 사유, 기기 기억, 제작부 서명.
- `availabilityMerge.ts`, `availabilityStore.ts`: 설정 권한, 작성자 검사, 초기·실시간 조회, 저장 직전 검사, 한 번의 게시, 교체 시 이어받기.
- `useAvailabilityPrivacy.ts`, `useTeamSprint.ts`: 계정·팀·제작부 모드별 사유 표시, 늦은 조회 결과 차단.
- `AvailabilityPanel.tsx`, `ProductionControls.tsx`, `AvailabilityRuleForm.tsx`: 짧은 한국어 폼, 버튼 권한, 사유를 바꾸지 않은 시간 수정 보존.
- `calendarImport.ts`: 보호된 백업/가져오기 보존.
- `identity.rs`, `tauri.ts`: 본인 계정에서 보내는 사람을 지정해 사유 읽기. 기존 본인용 호출은 그대로 동작한다.
- `availabilityPrivacy.test.mjs`: 결정성·타인 읽기 실패·작성자 변조/삭제/해제 거부·제작부 수정·평문 호환·설정 전 동작·게시 실패·비밀번호 교체·백업 보존.
- `availabilityPrivacy.jsdom-test.mjs`: 실제 캘린더/훅에서 설정·열기·잘못된 비밀번호·재열기·잠그기·예전 사유 숨기기·제작부 수정·실시간 변조·늦은 사유 읽기.

검사 명령: `pnpm -C desktop test`, `pnpm -C desktop exec tsc --noEmit`, `pnpm -C desktop build`, 네이티브 `cargo test --manifest-path desktop/src-tauri/Cargo.toml --features mesh-llm availability_reason`와 `team_calendar_export`. 깨끗한 `desktop-v0.5.28`에 전체 패치를 번호순 `git apply --3way` 후 트리를 비교한다.

## 5. 적용·확인

팀원 모두 107 적용본을 사용한다. 구버전은 이 읽기 검사를 하지 않는다. 이미 다른 기기에 배포된 평문·과거 이벤트·파일을 삭제하는 기능은 아니다. 개인 사유에만 적용하는 팀판 결정이며 일반 대화·일정의 검색/접근 모델은 그대로다.

가짜 팀원·가짜 사유로 다음 순서를 확인한다: 관리자 설정 → 일반 팀원의 사유/수정 버튼 숨김 → 잘못된 비밀번호 → 올바른 비밀번호로 제작부 열기 → 사유와 수정 버튼 표시 → 잠그면 다시 숨김 → 예전 사유 숨기기 → 새 비밀번호로 열기. 실제 팀 자료의 게시·배포·사람의 직접 확인은 별도다.
