# 105-team-hub.patch — 팀 기능 6타일 · 본문 일정

자주 쓰는 팀 기능을 큰 버튼 여섯 개로 모으고, 일정은 채널 본문 자리 전체를 쓴다. 기존 104·104b 작업의 새 번호는 105다.

- 기준: `desktop-v0.5.28` + `10`~`104` 패치.

## 1. 범위

- 사이드바 **팀 기능** → 일정 / 회의 시작 / 채널 파일 / 주간 공지 / 알림 설정 / 사용법.
- 큰 아이콘 타일 전체가 버튼이다. 기본 3열, 좁은 화면 2열이며 기존 색·글꼴·공유 UI를 쓴다.
- 일정 → `/schedule` 본문 전체 화면. 첫 팀 캘린더 탭은 103 스프린트·달력·팀원 일정·가져오기·배포를 그대로 보여 준다.
- 상단 알약 탭, 새로고침, ⋯ 메뉴. 기기 주소와 관리 폼은 메뉴에서 연다.

## 2. 동작

- 회의는 현재 채널 미트 조회·선택 함수를 재사용한다. 방이 없거나 채널 미선택이면 새 미트다. 조회 실패는 다시 누를 수 있게 알린다.
- 채널 파일은 현재 채널의 기존 파일 모아보기를 연다. 미선택이면 채널 선택 안내다.
- 주간 공지·알림은 기존 화면으로 연결한다. 사용법에서 처음 안내를 다시 열 수 있다. 설정 내용은 유지한다.
- 일정 진입·이탈은 기존 라우터와 내비게이션 가드를 따른다. 채널을 누르면 일반 화면으로 돌아온다.
- 메뉴·폼·모달이 열리면 104 웹뷰를 숨긴다. 방장·관리자만 탭 편집 메뉴를 본다. 순서 편집은 한 이벤트로 저장한다.
- 새로고침은 캘린더의 열린 달·스프린트 설정·팀원 일정을 다시 읽는다. 달 조회의 오래된 응답은 최신 요청을 덮지 않는다.

## 3. 의도

새 저장 모델을 만들지 않고 기존 기능의 입구와 화면 크기를 정리한다. 103 캘린더와 104 웹뷰 동작을 한 본문에 합치고 기존 캘린더 다이얼로그도 유지한다.

## 4. 파일·검증

- `features/team-hub/`: 타일·동작 연결·사용법.
- `features/team-schedule/ui/TeamScheduleView.tsx`, `TeamScheduleScreen.tsx`, `ScheduleOrderForm.tsx`: 본문 일정·메뉴·순서 편집.
- `app/routes/schedule.tsx`, 앱 내비게이션·설정 그룹.
- `features/team-calendar/lib/useTeamCalendar.ts`, `ui/TeamCalendarDialog.tsx`: 새로고침 연결과 공유 내용.
- DOM 테스트: 타일 동작·권한·진입/이탈·메뉴·로컬 주소·순서의 단일 저장·새로고침.
- `tests/e2e/team12.spec.ts`: 브라우저 mock bridge에서 실제 입구·본문 경로·다이얼로그 경로 확인.

## 5. 한계

브라우저 mock bridge는 네이티브 웹뷰의 실제 표시와 로그인까지 검증하지 못한다. 해당 항목은 네이티브 실기 확인 대상이다.
