# 102-team-welcome.patch — 팀 환영 안내 · 기본 채널

새 팀원이 처음 접속하면 관리자가 정한 **기본 채널**에 한 번 자동으로 들어가고, 5단계 **환영 안내**가 한 번 뜬다. Buzz Team 0.7 빌드(SHIBAL, `EugeneBot01/buzz-app` c4da1572)의 같은 기능을 0.5.28 코드에 새로 구현한 것.

- 기준: `desktop-v0.5.28` + `10`~`99` 패치 위에 적용.

## 1. 동작

- **기본 채널 정하기**: 설정 → 팀 안내(커뮤니티 묶음). 방장·관리자에게만 공개 채널 체크 목록이 보인다. 저장하면 그 커뮤니티의 기본 채널이 된다.
- **새 팀원 판정**: 이 기기에서 처음 실행할 때, 들어가 있는 팀 채널(최대 5개)의 멤버 목록에서 내 `joinedAt`을 읽어 가장 이른 값이 7일 안이면(또는 어느 채널에도 없으면) 새 팀원. 서버는 다시 들어온 사람의 `joined_at`을 처음 값으로 둔다(`channel_members` `ON CONFLICT`가 `joined_at`을 안 바꿈) — 그래서 노트9 `auto-invite.py`가 첫 실행 전에 방에 넣어도, 나갔다 다시 들어와도 판정이 맞다.
- **새 팀원**: 아직 안 들어간 기본 채널(공개만)에 들어간다. 안내 창 2단계에 넣어 준 채널 이름이 나온다.
- **기존 팀원**(업데이트로 처음 실행): 그 순간 안 들어가 있는 공개 채널 전부와 현재 기본 채널을 "처리함"으로 적고 아무 데도 넣지 않는다. 그 뒤로는 **업데이트 뒤에 새로 만든 채널**이 기본 채널로 체크될 때만 한 번 들어간다. 한 번 들어갔다 나간 채널에는 다시 넣지 않는다.
- **안내 창**은 새 팀원·기존 팀원 모두 그 기기에서 처음 실행할 때 한 번 뜬다(구윤 결정 11-04). 건너뛰기 가능.
- 안내는 설정 → 팀 안내 → "안내 다시 보기"로 누구나 다시 연다.
- 노트9 `auto-invite.py`는 그대로 둔다. 그쪽은 2분마다 모든 멤버를 고정 4개 방에 넣고 나가도 다시 넣는다(서버 쪽 강제). 이 패치는 그 4개 밖의 채널을 관리자가 앱에서 고르는 용도다.

## 2. 저장 형식 (0.7 빌드와 같음)

- 관리자마다 `(pubkey, kind 30078, d = "team-onboarding:<정규화한 릴레이 주소>")`, 태그 `["t","team-onboarding"]`, 평문 JSON `{ version: 1, channels: [{ id, name }], updatedAt }`(최대 30개).
- 읽는 쪽은 릴레이 멤버 목록(NIP-43)에서 **방장·관리자**가 쓴 문서만 보고, 그중 가장 최근 것 하나를 쓴다. 일반 멤버가 같은 키로 올려도 무시된다.
- 이 기기에서의 진행(안내 봤는지, 처리한 채널 id)은 `localStorage`의 `buzz-team-welcome:<pubkey>:<릴레이>`에 둔다. 기기마다 따로다.
- 0.7 빌드와 키·내용이 같아서, 같은 커뮤니티라면 어느 쪽에서 정한 기본 채널이든 서로 읽는다(0.7 앱이 파라 커뮤니티에 붙는지는 확인 못 함).

## 3. 의도 (패치가 안 붙으면 이걸 보고 다시 구현)

- 관리자만 정할 수 있고, 읽을 때도 관리자 문서만 믿는다.
- 기본 채널 가입은 기기·멤버마다 채널당 한 번. 나간 채널은 다시 안 넣는다. 기존 팀원은 업데이트 순간에 있던 채널에 절대 끌려 들어가지 않는다.
- 기본 채널 문서나 가입 시각을 못 읽으면 아무것도 적지 않고 다음 실행에 다시 한다(추측해서 넣지 않음). 목록에 팀 채널이 하나도 없으면(아직 안 받아짐) 기다린다.
- 채널 목록(스냅숏)에 아직 없는 채널은 처리함으로 적지 않고 다음 실행에 다시 본다. 비공개로 바뀐 채널은 건너뛴다.
- 안내 문구는 이 팀판 화면 기준(왼쪽 위 캘린더, 채널 둘러보기 +, 오른쪽 클릭 → 알림, 채널 위 연결·파일 버튼).

## 4. 파일

## 5. 알려진 한계

- 진행 기록은 기기마다다. 기존 팀원이 새 맥에 깔면 그 맥에서도 기존 팀원으로 판정된다(7일 기준).
- 관리자 판별은 릴레이 멤버 목록(NIP-43, kind 13534)의 역할에 의존한다. 파라 릴레이에 13534는 있음(auto-invite가 읽음), **역할 태그가 들어 있는지는 확인필요** — 설정 → 커뮤니티에 "초대" 탭이 보이면 같은 조회가 관리자로 인식한 것.
- 가입 시각을 읽으려고 첫 실행에 채널 멤버 조회를 최대 5번 한다(이후 실행엔 안 함).
- 확인한 것: 타입 검사, 전체 데스크톱 테스트 7,093개 통과, 새 파일 lint 0건, `pnpm build`(OSS 보호 검사 포함) 통과, `desktop-v0.5.28`에 `10`~`99` 뒤로 깨끗이 적용. **실제 앱 빌드·두 계정 실기 확인은 아직.**
