# 40-korean.patch — 한국어 UI

공식 Buzz 데스크톱 화면을 한국어로 보여 주는 패치. 설정 → 모양 → **"한국어 UI (Korean)"** 스위치로 켜고 끈다(기본 켜짐, 끄면 영어 원문 + 앱 새로고침).

- 기준: `desktop-v0.5.26` + `10`·`20`·`30` 패치 위에 적용, 이 순서로 `git apply --3way` 검증 완료.
- 검증: desktop 단위 테스트 6,770개 + scripts 93개 통과, `tsc` 통과, `pnpm build`(OSS 보호 기능 검사 포함) 통과.
- 번역 규모: 화면 문구 정확일치 2,446개 + 문장 패턴(값이 들어가는 문장) 321개.

## 1. 동작 방식 — 표시 계층 번역

컴포넌트 코드를 고치지 않고, React가 그린 **영어 문구를 화면에서 바로 한국어로 바꾼다.** 그래서 공식 업데이트가 와도 충돌이 거의 없고(새 파일 3개 + 연결 3곳), 새로 생긴 영어 문구는 영어로 남을 뿐 깨지지 않는다.

- `desktop/src/shared/i18n/domTranslator.ts`: MutationObserver로 텍스트 노드와 `placeholder`/`title`/`aria-label`을 사전과 **정확히 일치할 때만** 바꾼다. `{0}` 같은 값이 들어가는 문장은 패턴으로 매칭한다. 원문은 WeakMap에 보관해 React가 다시 그려도 올바르게 재번역한다.
- **문장 단위 번역**: JSX `Saves kind {n} events…`처럼 한 요소 안에서 인접 텍스트 노드로 쪼개진 문장은 합쳐서 통째로 번역한다(한국어 어순 대응). 결과는 첫 노드에 넣고 나머지는 비운다.
- **사용자 콘텐츠는 절대 번역하지 않음**: 메시지 본문(`.message-markdown`), 편집기(`[contenteditable]`), 입력창, `pre`/`code`, `[data-no-translate]` 하위는 건너뛴다.
- `desktop/src/shared/i18n/ko.generated.ts`: 번역 사전(생성물). 앱 시작 시 한국어일 때만 동적 import(`main.tsx`).
- 설정 스위치: `AppearanceSettingsControls.tsx`의 `UiLanguageSetting`, `SettingsPanels.tsx`의 모양 그룹 맨 위. localStorage 키 `buzz-ui-locale`.

## 2. 번역 과정 (품질 근거)

1. 코드에서 문구 추출(JSX 텍스트, 보이는 속성, toast, 라벨 맵, 값이 들어간 문장 전체) — 파일·줄·주변 코드 포함.
2. 용어집 기준 1차 번역 → **"사람이 실제로 쓰는 말" 기준으로 전면 재작성**(번역투·개발 용어 제거, 예: "관찰 프레임 보관" → "에이전트 작업 과정 기록").
3. **독립 검수 9개**(묶음별 8 + 전체 용어 일관성 1)로 뜻 오류·번역투·용어 불일치 수정. 용어집 때문에 오히려 딱딱해진 수정은 제외(Trace=실행 내역, 스냅샷 등).
4. 제외: 개발자용 내부 오류, 브랜드·모델명, 다른 곳 버튼을 오염시킬 수 있는 짧은 문장 조각, OSS 빌드 보호 문구(bestie/chief of staff), `ncryptsec`(보안 소스 스캔 대상).

## 3. 의도 (충돌 시 재구현 기준)

- 컴포넌트 수정 없이 **표시 계층에서만** 번역한다(업스트림 충돌 최소화가 최우선).
- 사전에 있는 문구만, 사용자 콘텐츠 영역 밖에서만 바꾼다. 확실하지 않으면 영어로 둔다.
- 업스트림이 정식 i18n을 도입하면(#2929, #7478) 이 패치는 버리고 사전을 `ko` 카탈로그로 기여한다. (#2929에 제안 댓글 남김)

## 4. 새 공식 버전이 나와서 영어 문구가 늘었을 때

새 문구만 골라 번역해서 사전에 더하면 된다(이번 0.5.26 반영 때 새 문구는 80개였다 — 대부분 새 관리자 콘솔).
1. `extract.cjs`로 새 태그 기준 문구 추출 → 기존 번역에 없는 문구만 추림
2. 용어집(`GLOSSARY.md`) 기준 번역 — 반복 작업이라 **Sonnet 5.5**로 충분
3. `merge.py`로 `ko.generated.ts` 재생성 → `tsc`/`pnpm test`/`pnpm build` → 패치 재생성

추출·병합 스크립트와 용어집은 구윤 맥 `~/Projects/buzz-patch/i18n/`에 있다(필요하면 이 폴더에 함께 올릴 수 있음).

## 4-1. 사용자 글자를 번역하던 문제 수정 (team.10)

**증상.** 메시지 본문 밖의 사용자 글자(영어로 된 채널 이름, 제목, 미리보기)가 번역됐다. 예: "Edit the doc" → "the doc 편집", "New York trip" → "새 York trip".

**원인.** `Edit {0}`, `New {0}`, `{0} only`처럼 원문에 고정 단어가 하나뿐인 패턴(321개 중 92개)은 평범한 문장에도 맞는다.

**수정 (`domTranslator.ts`).** 고정 단어가 하나 이하인 패턴은, 캡처한 값이 전부 공백 없는 한 덩어리일 때만 적용한다. 다만 UI 문구가 확실한 경우에는 예전처럼 여러 단어도 받는다: JSX가 인접 텍스트 노드로 쪼갠 문장(`Edit {name}`), `aria-label`, `placeholder`. `title`은 채널·파일 이름이 들어갈 수 있어 엄격하게 본다.

**남는 한계.** 두 단어짜리 사용자 글자("Share plans" → "plans 공유", "Alice's card" → "Alice 카드")는 여전히 번역된다. 반대로 한 텍스트 노드로 그려진 UI 문구에 공백 있는 이름이 들어가면("Edit My Agent") 영어로 남는다.

## 5. 알려진 한계

- 화면이 처음 그려질 때 영어가 아주 잠깐 비칠 수 있다.
- 코드가 영어 단어를 직접 끼워 넣는 몇 곳은 번역 사전만으로 안 고쳐진다: 채널 첫 화면 "This is the beginning of the {kind}."의 어미, 약관 동의 문장의 " and ", "Capture {n} sec video" 어순, 일부 영어 복수형 조각.
- 네이티브 메뉴(트레이 등 Rust 쪽 문구)는 번역되지 않는다.
